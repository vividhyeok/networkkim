Client-Server vs P2P 구조

네트워크 앱은 라우터가 아닌 End System에서 동작합니다.

Client-Server

항상 켜져 있는 Server 중심
고정 IP 주소 사용
Client끼리는 직접 통신 불가
관리 용이, 높은 보안/안정성
서버 병목 (Scalability 한계)

P2P (Peer-to-Peer)

항상 켜진 중앙 서버 없음
임의의 Peer들이 직접 통신
동적 IP, 간헐적 연결
Self-scalability: Peer 증가 시 용량도 증가
관리 어려움, 보안 취약
통신 원리

Process와 Socket

프로세스는 문(Socket)을 통해 네트워크로 데이터를 내보냅니다.

Application Process
메시지 생성
→ Socket →(API)
Transport Layer
TCP / UDP

프로세스 식별 (Addressing)

호스트 식별자 = IP 주소 (32-bit IPv4)
프로세스 식별자 = Port 번호 (예: HTTP 80, Mail 25)
목적지 = 192.168.1.10 : 80
웹 프로토콜

HTTP 기본 & 메시지 구조

웹은 TCP 위에서 동작하는 Stateless 프로토콜인 HTTP를 사용합니다.

Request Message

GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0
Accept-Language: ko-KR

(entity body - POST인 경우)
방식: GET, POST, HEAD, PUT

Response Message

HTTP/1.1 200 OK
Date: Tue, 02 Jun 2026 09:00:00 GMT
Server: Apache/2.4.41
Content-Type: text/html

<html>...</html>
상태: 200(OK), 301(Moved), 404(Not Found)
💡 Non-persistent vs Persistent HTTP
Non-persistent는 객체마다 TCP 연결을 새로 맺어 RTT가 낭비되지만, Persistent는 연결 하나로 여러 객체를 주고받습니다.

네임 시스템

DNS (Domain Name System)

도메인 이름을 IP 주소로 변환하는 분산 데이터베이스 시스템.

중앙집중형이 아닌 이유

단일 장애점 (Single point of failure)
전 세계 트래픽 집중 (Traffic volume)
물리적 거리에 따른 지연 (Delay)

DNS Hierarchy

Root DNS Servers
TLD DNS Servers (.com, .kr)
Authoritative DNS Servers

주요 레코드(RR) 타입

Type A : 도메인 이름 → IPv4 주소
Type NS : 도메인의 권한 네임서버
Type CNAME : 별칭(Alias) → 정식 이름
Type MX : 메일 서버 이름
P2P 분산 공유

BitTorrent & 파일 공유 구조

서버 한 대가 고통받지 않고, 파일을 받는 사람들이 직접 조각(chunk)을 나눠줍니다.

BitTorrent 핵심 메커니즘

파일을 256KB 크기의 Chunk들로 나눕니다.
Tracker: 토렌트에 참여 중인 Peer들의 IP 목록을 관리하고 새 Peer에게 알려줍니다.
Rarest First: 네트워크에 가장 희귀한 조각을 먼저 요청하여 분산을 극대화합니다.
Tit-for-Tat: 나에게 데이터를 잘(빠르게) 보내주는 Peer 4명에게 우선적으로 데이터를 보냅니다. (이기적인 노드 배제)
Client-Server 전송 시간
클라이언트 수 N이 증가하면 서버 업로드 부담이 N배로 증가하여 O(N)으로 시간이 늦어집니다.
P2P 전송 시간
클라이언트가 늘어나면 업로드 용량도 같이 늘어나 전송 시간이 일정 수준으로 수렴합니다.
멀티미디어

Video Streaming: DASH & CDN

Netflix, YouTube가 버퍼링 없이 고화질을 서비스하는 원리

DASH

Dynamic Adaptive Streaming over HTTP
동일한 영상을 여러 해상도/비트레이트 버전으로 쪼개서 서버에 저장
클라이언트(브라우저)가 자신의 현재 네트워크 상태(대역폭)를 보고 적절한 화질의 조각(Chunk)을 요청
네트워크가 느려져도 영상이 끊기지 않고 화질만 낮아짐

CDN

Content Delivery Network
단일 거대 서버 대신, 전 세계 수많은 지역 엣지 서버(Node)에 콘텐츠 복사본 분산 배치
유저가 접속 시 가장 가까운/빠른 CDN 노드로 연결 (Request Routing)
글로벌 딜레이 감소, 본서버 부하 분산
시험 대비

2장 시험/복습 체크리스트

이 질문들에 대답할 수 있다면 Application Layer는 마스터한 것입니다.
